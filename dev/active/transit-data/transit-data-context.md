## 이 태스크가 뭔가

수도권 지하철 그래프와 만남 거점 데이터를 만드는 파이프라인. 설계 `docs/transit-data-design.md`, 계획 `transit-data-plan.md`. 15개 태스크를 서브에이전트로 구현하고 태스크별 리뷰, 최종 브랜치 리뷰, 수정 1회를 거쳤다.

## 상태

- 테스트: `backend/`에서 `.venv/Scripts/pytest -q` 214 passed.
- `python -m pipeline.run_all` 검증 통과. 산출물: 역 791, 간선 768(실측 271), 그룹 646, 환승 181(실측 103), 시간표 124,978행(791 x 거점 노드 158).
- 로컬 `dev.db`에 적재됨. 서버 기동 후 3명, 4명, 2명 방에서 추천 5곳과 맛집 콘텐츠 확인.
- 카카오 REST 키는 `.env`에 있음. 서울 열린데이터광장, KOPIS 키는 아직 없음.

## 계획에서 벗어난 결정 (원장에서 옮김)

1. 속도 상수는 두 번 재보정했다. 처음 32/45/80, 1차 60/75/110, 최종 43.4/61/110. 결정적 발견은 서울교통공사 소요시간이 정차를 뺀 운행시간이라는 것. 그래서 실측 간선에도 정차 0.5분을 더한다.
2. 환승 시간은 서울교통공사 파일의 도보 시간에 대기 2.5분을 더한다(파일 값은 1.2m/s 도보뿐). 기본값 4.0분은 그대로. 2.5는 기본값과 맞추려고 고른 값이지 측정값이 아니다.
3. 원본 파일 결함을 config 표로 보정한다: `SEGMENT_PATCHES`(순서 오류와 지선 시작점), `STD_LINE_OVERRIDES`(경원선 용산~왕십리를 경의중앙선으로), `STD_COORD_OVERRIDES`(마곡, 이촌 좌표 복사 오류), `KRAIL_EXCLUDE`(중복 파일), `KRAIL_KM_DIRECTION`(파일별 km 방향, 미등록이면 실패), `EXPECTED_KM_DROPS`(버리는 이상치 12건, 늘거나 줄면 실패), `EDGE_LENGTH_ALLOWLIST`(실제로 긴 구간 8건).
4. GTX-A 9개 역과 표준데이터에 빠진 6개 역은 `manual/extra_stations.csv`로 보충(좌표 출처는 SOURCES.md).
5. 코레일 통합 파일의 1호선 일부 구간은 km가 한 칸 밀려 있다. 경로 합계에서 상쇄돼 1~2분 오차라 수용하고 SOURCES.md에 전환점을 기록했다.
6. 7호선 총신대입구(이수) 중복 행은 별칭 인식 중복 제거로 없앴다. 경의중앙선 광운대는 간선 없는 노드로 남아 있고 환승으로만 이어진다.
7. 거점 판교는 카카오 점수 182위(오피스 위주)지만 상식 검증에 쓰여서 예외로 넣었다.
8. `pipeline.load`는 hubs를 지우기 전에 `content_cache`의 hub 참조 행을 지운다(Postgres 외래키).
9. README에 스키마 변경 안내를 넣었다. 이전 DB는 테이블을 지우고 `init_db`부터 다시.

## 알려진 한계 (다음에 다룰 것)

- **역 id가 표준데이터 행 순서라 원본이 갱신되면 바뀔 수 있다.** 참가자의 `nearest_stations`는 역 id를 저장하므로 재적재 후 기존 방의 결과가 달라지거나 비어질 수 있다. 근본 해결은 (역번호, 노선) 기반 안정 id 또는 (name, line)을 함께 저장. 프론트는 `legs`가 비는 경우를 처리해야 한다.
- 소요시간에 배차 대기가 없다. 배차 간격이 긴 노선(GTX-A, 경의중앙선, 경춘선, 서해선) 경유 거점이 유리해질 수 있다. 다음 반복에서 탑승 대기(배차/2) 모델 검토.
- 타사 간 긴 환승(서울역 경의중앙선과 공항철도 등)에 기본 4분이 쓰인다. 수동 표로 보정할 만하다.
- regional 61은 실측이 아니라 비율로 정한 값. 9호선과 코레일 노선 실측을 시간표 API로 역산하는 것이 후속 과제.
- 표준데이터 2026-06-30판 기준. 7호선 청라 연장, 서해선 서화성, 신안산선은 파일에 없으니 운영자 노선도와 대조 필요.
- 일산 주엽이 거점 후보 150 밖(그룹 628 중심 좌표 점검).
- 수서 3호선과 "국철" 환승 1행은 노선 매핑이 안 돼 기본 4분 사용.

## 다음 계획에 넘길 것 (frontend)

- **지역 선택 (2026-09-28 결정, 아직 안 함):** 방 만들 때 서울/경기/인천 복수 선택 + 결과 화면 필터. 백엔드는 결과 API에 `region` 파라미터와 방의 기본 지역 저장. 예: 홍대/수원/잠실 방을 서울만으로 제한하면 1위가 판교(45분)에서 가락시장(55분)으로 바뀜.

- API 응답은 그대로. `hub_id`, `station_id`는 재적재 시 바뀔 수 있으니 URL이나 로컬 저장에 오래 두지 말 것.
- 결과 화면은 `status == "ready"`인데 추천이 비거나 `legs`가 빠진 경우를 처리.
- 소요시간은 "약 N분"으로 표기(배차 대기 미포함).
- 거점 태그 어휘(술집많음, 카페거리, 교통요지, 대학가, 밤늦게까지 등)가 hubs.csv에 확정됨.
- `/content` 응답은 `ContentOut(kind, items, error)`. `error` 문구와 만료 캐시 `items`가 동시에 올 수 있음.
- 참가자 20명 상한, `via == "bus"`면 "버스 15분" 표기.
