# transit-data 컨텍스트

Last Updated: 2026-09-28 (계획 작성 완료, 구현 전)

## 이 태스크가 뭔가

수도권 지하철 그래프와 만남 거점 데이터를 만드는 파이프라인. 설계는 `docs/transit-data-design.md`, 계획은 같은 폴더의 `transit-data-plan.md`. 백엔드(`backend/`)가 실제 추천을 내려면 이 데이터가 필요하다.

## 상태

- 백엔드 1단계는 `main`에 병합됨 (테스트 90개, `/health`, `POST /rooms` 확인).
- 카카오 REST 키는 `backend/.env`에 있고 카카오맵 서비스 사용 설정도 켜져 있음 (지오코딩, 장소 검색 확인 완료).
- 서울 열린데이터광장 키, KOPIS 키는 아직 없음 (행사 탭에만 필요, 이 계획과 무관).
- 브랜치: 계획 실행 시 `feat/transit-data`를 `main`에서 만든다.

## 확정된 결정

- 소요시간: 1~8호선은 서울교통공사 실측, 나머지는 거리 기반 추정 (urban 32, regional 45, gtx 80 km/h, 정차 0.5분). 1~8호선 실측으로 urban 속도 보정 후 상수 갱신 여부 판단.
- 역 그룹: 정규화 이름 같고 500m 이내면 한 그룹. 별칭 파일로 예외. 백엔드 매핑을 이름에서 group_id로 교체 (Task 1).
- 데이터 없는 6개 노선(우이신설, 신림, 김포골드, 의정부경전철, 서해선, GTX-A)은 역 순서를 수동 파일로.
- 거점: 카카오 장소 개수 점수 상위 150곳에서 지역 균형 맞춰 100곳 초안, 사용자 검토.
- 산출물 CSV와 원본을 저장소에 커밋, `pipeline.load`로 DB 적재. 원본 다운로드는 수동.
- station_times는 거점 노드 목적지 행만 저장 (약 14만 행).

## 2026-09-28 확인된 사실 (사용자가 원본 3개를 받아 넣음)

- `backend/data/raw/`에 표준데이터 XLSX(2026-06-30판, 1,099행), 서울교통공사 역간거리(2024-08-10판, 279행), 환승역(2026-08-31판, 145행)이 있음. 아직 커밋 전이면 Task 3에서 커밋.
- 표준데이터 헤더: 역번호, 역사명, 노선번호, 노선명, 영문역사명, 한자역사명, 환승역구분, 환승노선번호, 환승노선명, 역위도, 역경도, 운영기관명, 역사도로명주소, 역사전화번호, 데이터기준일자. 계획의 COLUMNS에 반영함.
- 경전철 5개사 역 포함. GTX-A 역은 없음 (Task 13에서 extra_stations.csv로 보충).
- 1호선 코레일 구간 노선명: 경부선, 경원선, 경인선, 장항선. 4호선 코레일 구간: 안산과천선, 진접선. 3호선: 일산선. 8호선: 수도권 광역철도 8호선(별내선). 9호선은 "서울 도시철도 9호선"과 "수도권  도시철도 9호선"(공백 2개) 두 표기. 인천은 "인천지하철 1호선/2호선". 공항철도는 "인천국제공항선". 의정부경전철은 "의정부". 신림선은 "수도권 경량도시철도 신림선". 전부 LINE_ALIASES에 반영함.
- 서울교통공사 두 파일: cp949, 호선은 숫자만("1"), 소요시간과 환승소요시간은 mm:ss. `canonical_line`이 숫자를 "N호선"으로 바꾸고 `parse_duration`이 mm:ss를 분으로 바꾸도록 계획 수정함.

## 남은 불확실성 (Task 3, 13, 15에서 해소)

- 국가철도공단 노선별 역간거리 CSV 십여 개는 아직 없음. 에이전트가 먼저 받아 보고, 로그인이 필요하면 사용자에게 목록 전달.
- 공항철도 파일에 소요시간 컬럼이 있는지.
- 지선 구간이 원본에서 별도 세그먼트로 시작하는지 (0분, 0km 행으로 판단). 서울교통공사 파일에서는 1호선 서울역, 2호선 시청 등 노선 첫 역이 00:00, 0으로 시작하는 것을 확인함.
